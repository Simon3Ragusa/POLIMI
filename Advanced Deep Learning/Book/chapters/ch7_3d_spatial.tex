\chapter{3D Spatial Data \& Point Clouds}
\label{ch:3d_spatial_data}

Visual recognition tasks such as image classification, object detection, and instance segmentation have seen superhuman performance when handling 2D images. However, the real 3D world is considerably more complex than 2D projections. There is an intrinsic ambiguity in the $3D \rightarrow 2D$ mapping: after projection, different depths cannot be distinguished in the image plane, meaning some information is fundamentally lost. Multiple views of the same scene help resolve these ambiguities; stereo vision systems leverage calibrated cameras and point correspondences to enable 3D reconstruction. Finding correspondences relies on extracting and normalizing region content, computing local descriptors, matching these descriptors, and performing robust model fitting. Developing deep learning models that directly consume 3D data enables systems to preserve spatial hierarchies, rich geometric features, and precise scale metrics.

\section{3D Data Representation}

Unlike images, which inherently come in an array format (a regular grid of pixels), 3D data are encoded in various ways, each with unique properties requiring different models and operations for visual recognition.

\subsection{Point Clouds}
Point clouds represent the canonical form of raw 3D data. They can be formalized as an unordered set of points in $\mathbb{R}^d$. Formally, a point cloud $P$ is defined as $P \subset \mathbb{R}^d$. When $d=3$, it simply records the 3D coordinates $(x, y, z)$ of points. When $d>3$, additional information such as color (RGB triplets), surface normals, reflectance intensities, or other data-driven features are associated with the spatial coordinates. Point clouds are highly popular in autonomous driving, robotics, and mapping due to their direct output from sensors like LiDAR and depth cameras.
\begin{insightbox}[Advantages and Disadvantages of Point Clouds]
\textbf{Pros}: Point clouds offer a highly compact representation by not allocating memory for empty regions (free space). They can intrinsically adapt to provide denser representations in regions with finer details or closer to the sensor.
\textbf{Cons}: Points are scattered and unordered; they do not reside on a regular grid. Standard Neural Networks and CNNs are built for ordered vectors or grid-based arrays, making direct application impossible. Because points theoretically have zero volume, they do not explicitly represent the continuous 3D surface or topological connections. Furthermore, the coordinate representation heavily depends on the chosen reference coordinate system.
\end{insightbox}

\subsection{Voxels}
Voxels represent the 3D world as a discrete uniform grid $N \times N \times N$. In its simplest form, it contains binary values denoting occupancy: $V \in \{0,1\}^{N \times N \times N}$. Voxels can be easily generated by discretizing point clouds—setting a cell to 1 if it contains one or more points, and 0 otherwise. Intensity information or other features can also be stored inside voxels (e.g., in Medical Imaging like MRI and fMRI, where each voxel encodes tissue density or oxygenation).
While conceptually simple and structurally akin to 2D images (making it relatively easy to adapt standard 3D CNNs), voxel grids suffer from severe scalability issues. Volumetric data are typically exceedingly sparse (often $<5\%$ occupancy at moderate resolutions). Thus, capturing fine structures requires high spatial resolution, making the memory footprint and computational cost grow cubically ($\mathcal{O}(N^3)$), which is largely prohibitive.

\subsection{RGB-D and 2.5D Images}
RGB-D images add a fourth depth channel to the standard RGB pixel grid. These are considered \textit{2.5D images} because they do not capture the full 3D geometry; they suffer from occlusions (the structure behind visible objects is not captured) and missing values due to shadows, out-of-range depths, or non-reflecting surfaces. However, their matrix structure makes neighborhood computations trivial using standard pixel adjacency, allowing the reuse of mature 2D CNN backbones.

\subsection{Implicit Functions and Meshes}
An implicit function models a 3D object as a continuous function $f: \mathbb{R}^3 \rightarrow \{0,1\}$ (occupancy network) or $f: \mathbb{R}^3 \rightarrow \mathbb{R}$ (Signed Distance Function, SDF). The object surface is extracted as the 0-level set of $f$, often yielding infinite resolution and smooth surfaces. Neural Radiance Fields (NeRFs) use implicit coordinate-based neural networks to synthesize novel views.
Meshes are the standard representation in Computer Graphics, represented as a collection $(P, E, F)$ where $P \subset \mathbb{R}^3$ are the vertices, $E \subset \mathbb{R}^3 \times \mathbb{R}^3$ are the edges connecting vertices, and $F \subset \mathbb{R}^3 \times \mathbb{R}^3 \times \mathbb{R}^3$ are the triangular faces. Meshes are adaptive and efficient for flat surfaces, allowing native interpolation, but feeding them into Neural Networks requires specialized Graph CNN or Mesh-based architectures.

\section{3D Imaging Sensors and Datasets}

\subsection{Sensors}
\begin{itemize}
    \item \textbf{Computed Tomography (CT) Scan}: A diagnostic imaging technique that measures multiple X-rays from different angles. Tomographic reconstruction algorithms (like filtered back projection) produce virtual slices of a body, discretized into a grid of voxels containing the CT number (density).
    \item \textbf{LiDAR (Light Detection and Ranging)}: Active sensors comprising a laser source (IR, UV) and a sensor measuring reflected light time-of-flight (ToF). They emit pulses to sweep the scene and construct precise 3D point clouds. However, LiDAR lacks color information, has lower vertical resolution, and is sensitive to rain and harsh weather conditions. Examples include Innovusion Falcon K and Ouster OS1.
    \item \textbf{RADAR}: Operates similarly to LiDAR but uses radio electromagnetic emissions from an antenna. It is exceptionally robust to weather and allows detecting moving objects and estimating their relative velocity via the Doppler effect. RADAR point clouds are typically much sparser and noisier than LiDAR.
    \item \textbf{Coded Light / Structured Light}: Uses synchronized projectors and cameras. The projector emits high-frequency black-and-white patterns. The signature serves as a descriptor for dense correspondence matching to infer depth.
\end{itemize}

\subsection{Datasets}
\begin{itemize}
    \item \textbf{ModelNet}: The first large-scale 3D CAD dataset containing 151,128 models over 660 categories. Often used in 10 or 40 class variants for point cloud classification.
    \item \textbf{ShapeNet}: A richly annotated dataset of 53,100 CAD models across 55 categories. It includes rendered images and ShapeNetPart for fine-grained part segmentation.
    \item \textbf{ScanNet}: Scans from 1,513 indoor scenes with 3D camera poses, surface reconstructions, and semantic voxel labeling, acquired using RGB-D sensors.
    \item \textbf{Outdoor Datasets}: KITTI 360, nuScenes, and Waymo Open Dataset offer vast multi-modal autonomous driving data (LiDAR, Camera, Radar) labeled with 3D bounding boxes and semantic segmentation.
    \item \textbf{BraTS}: Brain tumor segmentation dataset containing 369 multimodal MRI scans with spatial resolution $240 \times 240 \times 155$, standardizing medical 3D segmentation benchmarks.
\end{itemize}

\section{Deep Learning on Voxelized Data}

A conventional 2D CNN utilizes locality-aware processing through convolutional layers followed by dense MLP layers. For 3D volumetric data (or videos treating time as the Z-axis), we intuitively extend this to 3D Convolutions. A 3D convolutional layer computes its output activation $a$ for a given spatial location and channel $k$ as:
\begin{equation}
a(x, y, z, 1) = \sum_{(u, v, s) \in U, k} w^1(u, v, s, k) X(r+u, c+v, d+s, k) + b^1
\end{equation}
The channel dimension aggregates all input features without spatial processing. To achieve spatial invariance globally, Global Average Pooling (GAP) or Global Max Pooling (GMP) is employed over the volumetric dimensions:
\begin{equation}
F_k = \frac{1}{H \cdot W \cdot Z} \sum_{(x,y,z)} f_k(x, y, z) \quad \text{for } k=1,\dots,C
\end{equation}

\begin{insightbox}[3D CNN Enhancements]
Standard 3D CNNs suffer from massive parameter counts, high memory requirements, and susceptibility to overfitting due to limited 3D data compared to 2D images. They can be improved by:
1. \textbf{mlpconv layers} to reduce overfitting risk by adding non-linear feature pooling.
2. \textbf{Auxiliary subvolume supervision} to predict object classes from portions of the latent space, forcing local feature discriminability.
3. \textbf{Anisotropic Probing}: using elongated 3D kernels (e.g., $1 \times 3 \times 3$) to increase the receptive field without exploding the parameter count.
4. \textbf{Orientation-Pooling}: training a backbone on standard orientations, generating features for multiple rotated 3D versions, and pooling them before final classification to achieve rotation invariance.
\end{insightbox}

To circumvent the staggering computational cost of native 3D convolutions, alternative representations like \textbf{Multi-View CNNs} (Su et al., 2015) render 3D shapes from multiple virtual cameras (e.g., 30 views) and apply mature 2D CNNs, followed by view-pooling. Another approach for video data is \textbf{(2+1)D Convolution}, which factors a 3D convolution ($3 \times 3 \times 3$) into a 2D spatial convolution ($1 \times 3 \times 3$) followed by a 1D temporal convolution ($3 \times 1 \times 1$), effectively adding non-linearity and improving optimization landscapes. Additionally, \textbf{OctTrees} leverage hierarchical adaptive cell sizes to losslessly reduce memory consumption in sparse voxel grids, recursively subdividing only the occupied space, although their kernels are rigidly constrained.

\section{Single Image Depth Estimation}

Estimating a depth map $M = (x,y,z)$ from a single RGB image is inherently ill-posed due to the \textit{scale-depth ambiguity}: a small close object perfectly mimics a large distant object on the 2D projection plane. Yet humans seamlessly infer depth using monocular visual cues like perspective, texture gradient, occlusions, relative lighting, shadows, and defocus. Modern approaches use Fully Convolutional Networks (like an Encoder-Decoder with skip connections, e.g., U-Net architectures) to predict depth maps in a supervised or self-supervised manner.

A naïve $\ell_2$ pixel-wise loss $D(y, y^*) = \|y - y^*\|_2^2$ fails because global scale errors dominate the training signal, ignoring local structural correctness. Thus, a \textbf{Scale Invariant Loss} is utilized to prioritize relative depth:
\begin{equation}
D(y, y^*) = \frac{1}{n} \sum_{i=1}^n \left( \log y_i - \log y^*_i + \alpha(y, y^*) \right)^2
\end{equation}
By setting $d_i = \log y_i - \log y^*_i$, the loss decomposes algebraically:
\begin{equation}
D(y, y^*) = \frac{1}{n} \sum_i d_i^2 - \frac{\lambda}{n^2} \left( \sum_i d_i \right)^2
\end{equation}
where $\lambda$ controls the scale invariance (e.g., $\lambda=0.5$). 
To preserve local geometric structures and sharp boundaries, a \textbf{Loss on Gradients} is introduced, penalizing discrepancies in depth derivatives:
\begin{equation}
l_{grad} = \frac{1}{n} \sum \left[ (\nabla_x d_i)^2 + (\nabla_y d_i)^2 \right]
\end{equation}
Furthermore, a \textbf{Loss on Normals} evaluates the cross-product of tangent vectors $l_{norm} = \cos(n, n^*)$ to ensure predicted surface normals align with ground truth normals.
Despite these advanced losses, single-image depth estimators suffer from epistemic uncertainty on Out-of-Distribution (OOD) objects and struggle to generalize reliably across drastically different camera intrinsics. Position in the frame often acts as a stronger cue than apparent size.

\section{Deep Learning on Point Clouds}

Due to the unordered, continuous, and unstructured nature of point clouds, voxelization implies data loss, quantization artifacts, and extreme inefficiency. Deep learning directly on point sets preserves exact geometry.
According to the \textbf{Deep Sets} theorem, a function operating on a set $X$ is invariant to permutations if it can be decomposed as $\rho \left( \sum_{x \in X} \phi(x) \right)$, where $\phi$ and $\rho$ are approximated via MLPs.

\subsection{PointNet and PointNet++}
The seminal \textbf{PointNet} (Qi et al., 2017) processes raw point clouds by employing symmetric functions to guarantee permutation invariance. PointNet uses a shared MLP to map each point $x_i$ individually into a high-dimensional feature space $h(x_i)$, applies a channel-wise global max pooling $g$ (the symmetric function), and passes the aggregated global feature through a final MLP $\gamma$ for classification. 
To handle rigid geometric transformations, PointNet includes a \textbf{T-Net} (Transformation Network) that dynamically predicts a $3 \times 3$ affine alignment matrix for input spatial coordinates and a $64 \times 64$ alignment matrix for intermediate feature spaces, enforced by an orthogonal regularization term $\mathcal{R}(A) = \|I - A^T A\|_F$. For point-wise tasks like semantic segmentation, the global feature vector is concatenated back to the individual point features before dense prediction.

PointNet's primary limitation is its failure to capture local geometric structures contextually. \textbf{PointNet++} (Qi et al., 2017) resolves this by introducing a hierarchical stack of \textit{Set Abstraction Levels}:
1. \textbf{Sampling Layer}: Uses Farthest Point Sampling (FPS) to select well-distributed anchor points, maximizing coverage of the geometric space.
2. \textbf{Grouping Layer}: Defines local neighborhoods (e.g., metric ball query or K-Nearest Neighbors) around each anchor point.
3. \textbf{PointNet Layer}: Applies a mini-PointNet to extract a local contextual feature vector for each neighborhood.
To handle varying sampling densities inherent in sensors like LiDAR, PointNet++ uses Multi-Scale Grouping (MSG) and Multi-Resolution Grouping (MRG) paired with random input dropout during training, ensuring robustness to distance-based sparsity.

\subsection{Point Convolutional Operators (KPConv)}
\textbf{KPConv} (Thomas et al., 2019) bridges the gap between discrete image convolutions and continuous point clouds. The convolution over a scattered neighborhood $\mathcal{N}_x$ is defined as:
\begin{equation}
(\mathcal{F} * g)(x) = \sum_{x_i \in \mathcal{N}_x} g(x_i - x) f_i
\end{equation}
The continuous spatial kernel $g$ is parameterized by a set of $K$ learnable weight matrices $W_k$ associated with explicitly defined rigid anchor points $\tilde{x}_k$:
\begin{equation}
g(y_i) = \sum_{k \le K} h(y_i, \tilde{x}_k) W_k
\end{equation}
where $h(y_i, \tilde{x}_k) = \max \left(0, 1 - \frac{\|y_i - \tilde{x}_k\|}{\sigma} \right)$ calculates the interpolation weights based on Euclidean distance to the anchor points. This formulation closely mimics image convolutions but operates in continuous metric space.

\begin{insightbox}[Composite Convolutions]
Recent architectures propose separating spatial and feature processing. The Spatial Function extracts purely geometric structure features, which are then multiplied with semantic feature vectors. This factorization acts as a strong structural regularizer, allowing lighter and faster network architectures to match or exceed KPConv's performance while significantly reducing the parameter count.
\end{insightbox}

\section{Autonomous Driving Applications}

Autonomous driving perception heavily relies on robust and real-time \textbf{3D Object Detection}. A 3D bounding box is parameterized by 7 core values: $[x, y, z, h, w, l, \theta]$ where $\theta$ is the yaw angle, alongside the object class. Pitch and roll are usually neglected as vehicles adhere to the ground plane. LiDAR point clouds in this domain feature up to 150k points per sweep, 360-degree environmental coverage, heavy occlusions, and severe anisotropic densities. Real-time operation (>10 fps) is absolutely mandatory for safe navigation.

\subsection{Grid-Based Detectors: Voxels and Pillars}
\textbf{Bird Eye View (BEV)} is a highly effective 2D representation that preserves horizontal spatial ranges and physical scale without perspective distortion, projecting the z-axis (height) into channel dimensions, drastically reducing computational overhead.

\textbf{Voxel-based models} like \textbf{SECOND} (Yan et al., 2018) discretize the cloud into 3D voxels. To counteract extreme volume sparsity, \textbf{Submanifold Sparse Convolutions} are utilized: convolutions are only evaluated at active (non-empty) spatial sites. This prevents the computational "dilation" of non-zero entries, strictly preserving sparsity and eliminating wasted operations in empty space, dramatically speeding up inference.

\textbf{PointPillars} (Lang et al., 2019) takes this further by discretizing space only in the $x,y$ plane, creating vertical "pillars" of unlimited z-axis dimension. Each point inside a pillar is augmented to a 9-dimensional vector (coordinates, reflectance, offsets to cluster mean, offsets to pillar geometric center). A simplified PointNet processes each pillar to yield a fixed-size representation. The scattered populated pillars are then scattered back to form a dense 2D BEV pseudo-image, seamlessly enabling the use of extremely fast standard 2D CNN detection heads (like SSD or CenterPoint architectures).

\subsection{Multimodal Learning: Fusion Strategies}
Autonomous vehicles simultaneously leverage LiDAR (provides precise 3D geometry and distance but is semantically sparse) and RGB Cameras (provides dense semantic details, color, and high resolution but lacks absolute depth). Calibrated extrinsic parameters permit accurate spatial alignment between the two spaces.
\begin{itemize}
    \item \textbf{Early Fusion}: Intermediate features from both modalities are extracted, spatially aligned, concatenated, and fused in a unified backbone. For instance, \textbf{BEVFusion} (Liu et al., 2022) independently extracts camera features, projects them into the BEV space using a learned View Transformer, concatenates them with LiDAR BEV features, and performs joint decoding. This provides rich context but is memory-intensive.
    \item \textbf{Late Fusion}: Independent 3D (LiDAR) and 2D (Camera) detectors yield separate predictions, which are merged post-hoc via heuristic Non-Maximum Suppression (NMS), Kalman filtering, or learned MLP ensembles. It is robust to single-sensor failure but misses synergistic feature combinations.
    \item \textbf{Cascade Fusion}: 2D camera detections generate 3D frustum proposals (Frustum PointNets). LiDAR points inside these specific frustums are isolated to run targeted 3D localization. This is computationally demanding as it requires running the 3D network sequentially per proposal and heavily relies on the recall of the 2D detector.
    \item \textbf{LCF3D (Late-Cascade Fusion)}: A state-of-the-art framework that executes fast late fusion first. The expensive cascade geometric refinement is triggered \textit{only} for unmatched camera detections (candidate false negatives from the LiDAR pipeline), dramatically improving recall for distant and small objects while maintaining strict real-time latency.
\end{itemize}
Stereo RGB-only or Monocular 3D detection architectures currently rank significantly lower on precision benchmarks (e.g., nuScenes, KITTI) compared to LiDAR or LiDAR+Camera systems, confirming that precise active geometric measurements remain indispensable for reliable autonomous navigation.
